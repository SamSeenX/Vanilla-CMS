# Project Rules: Vanilla-CMS

## 1. Architectural Mandates
- **Decoupled Companion**: Vanilla-CMS runs locally as an independent tool. It never injects files or runtimes into target SSG projects.
- **Zero Heavy Frameworks**: No React, Vue, Svelte, Tailwind, Express, or Prisma. Build strictly with modern Vanilla JS (ES6 modules), native CSS variables, and native Node.js APIs (`node:http`, `node:fs/promises`, `node:path`).
- **200-Line Code Rule**: Every source file (.js, .css, .html) must strictly remain under 200 lines. Proactively modularize before reaching 180 lines.
- **Safety First**: Target file paths must always be validated against directory traversal attacks (`../`).

## 2. UI & Design System Standards
- **Aesthetic**: Modern, minimalistic obsidian dark theme with emerald/kinetic accents.
- **Accessibility**: Maintain minimum WCAG AA contrast (4.5:1) for all text and form controls.
- **Zero Native Alerts**: Never use `window.alert()` or `confirm()`. Use custom modular toast and modal components.

## 3. Git Protocol
- Active work occurs exclusively on dedicated `feature/*` branches.
- Merge to `main` only on explicit save commands.
- Sync `main` to `deploy` only on explicit deploy commands.
